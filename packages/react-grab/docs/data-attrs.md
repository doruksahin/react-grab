# `data-react-grab-*` attributes

Naming rules for DOM identifiers used by the overlay (event boundaries),
Playwright tests (selectors), and debugging (devtools inspection).

The authoritative catalog lives in `architecture.yml` under `data_attrs` —
scopes are authored there, inventory is generated by `pnpm arch:codegen`,
and `pnpm arch:lint` validates that every attr in code maps to a declared
scope.

## Rules

### R1 — Every component root gets an identifier

```
data-react-grab-<component-name>
```

- One per root element, kebab-case.
- Name what the component IS, not where it sits in the tree.
- Examples: `data-react-grab-sidebar`, `data-react-grab-selection-card`.

### R2 — Interactive elements get a scoped action attr

```
data-react-grab-<scope>-<action>
```

- `<scope>` = parent component or feature name (e.g. `toolbar`, `comment`, `jira`).
- `<action>` = imperative verb (`submit`, `cancel`, `toggle`, `copy-all`).
- Always scope. Bare `-submit` / `-retry` / `-abort` collide across contexts
  and are flagged by `pnpm arch:lint` during the migration phase.
- Examples: `data-react-grab-comment-submit`, `data-react-grab-toolbar-collapse`.

### R3 — Collection items use paired attrs (type + value)

```
data-react-grab-<item-type>              ← identifies "this is an X"
data-react-grab-<item-type>-id="<value>" ← identifies WHICH X
```

- Splits identification from payload; yields clean test selectors like
  `[data-react-grab-comment-item][data-react-grab-comment-id="abc"]`.
- Preferred over inline value attrs like `data-react-grab-menu-item="Copy"`,
  which mix identification with payload.

### R4 — State/mode uses scoped boolean or enum attrs

```
data-react-grab-<scope>-<state>           ← boolean presence
data-react-grab-<scope>-<state>="<value>" ← enum
```

- Examples: `data-react-grab-toolbar-enabled`,
  `data-react-grab-active-group-picker-locked`.

## Reserved attrs

These are internal machinery and do not follow R1–R4:

| Attr | Meaning |
|---|---|
| `data-react-grab-ignore` | User-set; skip element from selection |
| `data-react-grab-ignore-events` | Don't route events through overlay |
| `data-react-grab-frozen`, `-frozen-pseudo`, `-frozen-styles` | Internal freeze machinery |
| `data-react-grab-global-freeze` | Global freeze flag |

## When to add an attr

Add one when a concrete consumer exists:

- A Playwright test needs to click or assert on the element.
- An event handler needs to detect it by attr.
- A devtool or external integration needs to find it.

**Do not** pre-emptively add attrs to every decorative wrapper, icon, or
layout container. Each attr is a de facto contract surface — more attrs =
more maintenance on rename.

## When renaming / deleting

Attrs are part of the de facto test API. To rename:

1. Update the declaration in the component.
2. Grep `e2e/` + `src/` for the old attr and update all selectors.
3. If the attr is in `architecture.yml` `data_attrs.scopes.*.owns`,
   update the scope entry.
4. Run `pnpm arch:codegen` to regenerate the inventory.
5. Run `pnpm arch:lint` to confirm no orphans or stale test selectors.

## How this is enforced

`pnpm arch:lint` fails CI when:

| Check | Fails when |
|---|---|
| Orphan attr | An attr in `src/` matches no scope in `data_attrs.scopes` and isn't reserved |
| Unused scope entry | A scope declares an attr in `owns` that doesn't appear anywhere in code |
| Stale test selector | An attr in `e2e/` doesn't appear in `src/` (test targets deleted element) |

Warnings (do not fail CI):

| Check | Warns when |
|---|---|
| Bare verb | An attr is a single imperative word with no scope prefix (e.g. `submit`) |

## Adding a new scope

When adding a new feature region:

1. Pick a kebab-case scope name (usually the component or feature folder).
2. In `architecture.yml` `data_attrs.scopes`, add:
   ```yaml
   <scope-name>:
     description: <one-liner>
     owning_feature: <feature-key>
     owns:
       - <scope-name>            # root per R1
       - <scope-name>-<action>   # actions per R2
       - <scope-name>-item       # collections per R3
       - <scope-name>-<state>    # state per R4
   ```
3. Add the attrs in JSX per R1–R4.
4. Run `pnpm arch:codegen` then `pnpm arch:lint`.
