Due Date Filter — UX POC

Two proposals for filtering sidebar tasks by due date. Both feed a JQL clause shown below the header (e.g. duedate < now()). The task list below each filter updates live.

Option A — Preset Select (minimalist)

A 5th Select added to the existing FilterBar. Same primitive, same size, same behavior as Status / Assignee / Reporter / Label. Zero new UI vocabulary.

Trade-offs

Dimension A — Preset Select B — Popover + Range Calendar
Footprint in filter bar 1 select, same size as the other 4 — fully consistent. 1 trigger button, but the popover is 420px wide when open.
Implementation cost Reuses existing Select primitive. ~40 lines. New primitives: Popover + Calendar (Kobalte). ~300+ lines.
Coverage of JQL ~6 common presets. Custom ranges not supported. Presets + arbitrary range → any duedate >= X AND <= Y.
Cognitive load Minimal — single click, labeled option. Higher — user decides between preset column and calendar grid.
Matches current sidebar style Yes — identical to the other 4 filters. Breaks uniformity — the only popover-based filter.
Mobile / narrow sidebar Wraps naturally with the other selects. Popover overflows; needs responsive layout.
shadcn-solid proposal Just Select (already used). DatePicker / RangePicker built on Kobalte's DatePicker.

Recommendation

Option A is the right call for v1 — it matches your existing filter vocabulary, costs almost nothing to build, and covers the 90% case (overdue, today, this week, no date). Ship A first; if users start asking for specific date ranges ("show me everything due between June 10 and June 20"), upgrade to B — but only behind a "Custom range…" entry in the preset list, so the simple case still stays one click.
