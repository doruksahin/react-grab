The one people ask for

Changing the Jira connection

Four separate things decide where a ticket ends up. They live in three different places, so change the right one.

Which Jira sitethe company's Atlassian instance
JIRA_BASE_URL under [vars] in packages/sync-server/wrangler.toml. Not a secret, committed.
pnpm sync:dev
Restart the sync server after editing. For the deployed Worker, redeploy.
Which accounttickets are created as this user
JIRA_EMAIL in packages/sync-server/.dev.vars for local work. In production set it on the deployed Worker, never in a committed file.
Copy .dev.vars.example to .dev.vars if you do not have one. It is gitignored.
The API tokensecret
JIRA_API_TOKEN in .dev.vars locally. Create one at id.atlassian.com.
pnpm --filter @react-grab/sync-server exec wrangler secret put JIRA_API_TOKEN
That is the production route. The token is stored encrypted by Cloudflare and never enters git.
Which projectwhich Jira project the ticket is filed in
Not server-side at all. The host application passes it: initSync({ jiraProjectKey: "ATT" }). It travels to the create dialog and to the issue-type, priority and label lookups.
Change it where the host app calls initSync, then restart that app. In this repo nothing calls initSync outside the test harness, so the only live caller is AdCreative-Frontend-V2.
Get it wrong and it says so. The three server values are validated by packages/sync-server/src/schemas/env.ts on the first request. A missing or malformed value fails with every problem named at once, instead of an opaque Jira 401 later. ADR-0018 explains why this is a plain Zod schema and not an env library.

Running the stack

Three terminals. The first build must finish before the host app starts, or its TypeScript cannot resolve react-grab.

First run, once
pnpm install && pnpm build
pnpm --filter @react-grab/sync-server db:migrate:local
The build writes the type definitions that watch mode then preserves.
Terminal 1 — library
pnpm dev
JS only, about 15–20s a rebuild. Use pnpm dev:full when you are changing public types and need the IDE to follow.
Terminal 2 — sync server
pnpm sync:dev
Worker on :8787. Swagger at /swagger, health at /health.
Terminal 3 — host app
pnpm dev
In AdCreative-Frontend-V2. Its node_modules/react-grab is a symlink here, so Vite HMR picks changes up.

When it breaks

Known traps

Two builds racing
Never run pnpm build while pnpm dev is watching in another terminal. Two tsup processes on one dist/ corrupt the output and wedge the watcher. Stop the watcher first.
Failed to resolve entry for "react-grab"
The host app started while tsup was mid-rebuild and cached the failure.
rm -rf node_modules/.vite
Run it in the host app, then restart its Vite.
Jira calls return 401
Check the account and token in .dev.vars, then restart pnpm sync:dev. Since ADR-0018 an empty value fails loudly on the first request instead, so a 401 now points at a wrong value rather than a missing one.
Tickets land in the wrong place
Site is JIRA_BASE_URL in wrangler.toml; project is jiraProjectKey from the host app. They are set in different repositories, which is the usual cause of confusion.

Source of truth is the repository. Where this page and the code disagree, the code is right — and the page is wrong, so fix it at docs/react-grab-cheatsheet.html.
